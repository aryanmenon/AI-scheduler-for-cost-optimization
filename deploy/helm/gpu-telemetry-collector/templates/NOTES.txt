GPU telemetry collector installed into namespace {{ .Release.Namespace }}.

This deployed, read-only:
  - dcgm-exporter (DaemonSet on GPU nodes) -- per-GPU utilization/memory/power
  - kube-state-metrics                     -- pod/node metadata
  - telemetry-collector                    -- correlates the two and stores
                                               a time series in SQLite
{{- if .Values.ingestion.enabled }}
  - ingestion-normalization (sidecar)       -- derives workload identity,
                                               normalizes utilization by GPU
                                               capability, and rolls it up
                                               into 5-min/hourly/daily buckets
{{- end }}

Nothing here can create, update, or delete anything in your cluster --
every RBAC rule granted is get/list/watch only.

Check that GPUs are being scraped:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c telemetry-collector -f
{{- if .Values.ingestion.enabled }}

Check that ingestion is producing rollups:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c ingestion-normalization -f
{{- end }}

Once you're ready to hand this data to the waste-detector / dashboard,
telemetry.db lives at /data/telemetry.db inside the collector pod
{{- if .Values.persistence.enabled }} on a {{ .Values.persistence.size }} PersistentVolumeClaim.
{{- else }} on an emptyDir -- enable `persistence.enabled` before running a real pilot so data survives pod restarts.
{{- end }}
