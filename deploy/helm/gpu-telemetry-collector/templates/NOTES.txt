GPU telemetry collector installed into namespace {{ .Release.Namespace }}.

This deployed, read-only:
  - dcgm-exporter (DaemonSet on GPU nodes) -- per-GPU utilization/memory/power
  - kube-state-metrics                     -- pod/node metadata
  - telemetry-collector                    -- correlates the two and stores
                                               a time series in SQLite
{{- if .Values.ingestion.enabled }}
  - ingestion-normalization (sidecar)       -- derives workload identity,
                                               normalizes utilization by GPU
                                               capability, and rolls it up
                                               into 5-min/hourly/daily buckets
{{- end }}
{{- if .Values.wasteDetector.enabled }}
  - waste-detector (sidecar)                -- flags idle, over-provisioned,
                                               fragmented, and recurring-
                                               pattern GPU waste from those
                                               rollups
{{- end }}
{{- if .Values.savingsEstimator.enabled }}
  - savings-estimator (sidecar)             -- prices those findings into
                                               confidence-scored INR impact
                                               against an SLA-aware
                                               right-sizing ceiling
{{- end }}
{{- if .Values.dashboard.enabled }}
  - dashboard (sidecar + Service)           -- the self-serve sales
                                               artifact: renders those ₹
                                               estimates as a live report
{{- end }}

Nothing here can create, update, or delete anything in your cluster --
every RBAC rule granted is get/list/watch only.

Check that GPUs are being scraped:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c telemetry-collector -f
{{- if .Values.ingestion.enabled }}

Check that ingestion is producing rollups:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c ingestion-normalization -f
{{- end }}
{{- if .Values.wasteDetector.enabled }}

Check that waste findings are being produced:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c waste-detector -f
{{- end }}
{{- if .Values.savingsEstimator.enabled }}

Check that ₹ savings estimates are being produced:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c savings-estimator -f

IMPORTANT: savingsEstimator.gpuHourlyRatesJson is empty by default, which
means estimates are priced against illustrative Indian GPU-cloud list
rates, not your actual cost. Set it to your contracted INR/hour rates
before trusting any rupee figure this produces.
{{- end }}
{{- if .Values.dashboard.enabled }}

The dashboard requires a bearer token. Retrieve the one this install
generated (or set yourself via dashboard.authToken):

  kubectl -n {{ .Release.Namespace }} get secret {{ include "gpu-telemetry-collector.fullname" . }}-dashboard-auth -o jsonpath='{.data.DASHBOARD_AUTH_TOKEN}' | base64 -d; echo

View the report:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "gpu-telemetry-collector.fullname" . }}-dashboard {{ .Values.dashboard.port }}:{{ .Values.dashboard.port }}

then, with the token above:

  curl -H "Authorization: Bearer <token>" http://localhost:{{ .Values.dashboard.port }}/

kubectl port-forward is safe to use as-is here -- it's tunneled through
the Kubernetes API server's own TLS/mTLS, so the token and every cost
figure in the report stay encrypted end to end.
{{- if ne .Values.dashboard.serviceType "ClusterIP" }}

*** dashboard.serviceType is "{{ .Values.dashboard.serviceType }}", not the
*** default ClusterIP -- that exposes the dashboard beyond port-forward
*** with NO TLS of its own. You MUST terminate TLS in front of it
*** (an Ingress with TLS, a load balancer with TLS passthrough disabled
*** and a cert attached, etc.) or the bearer token and all cost data in
*** the report travel in plaintext.
{{- end }}

The report always reflects the current data, no refresh/rebuild needed.
To generate a standalone HTML file to share (e.g. by email), run
`generate-report` inside the dashboard container:

  kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "gpu-telemetry-collector.fullname" . }}-collector -c dashboard -- generate-report
  kubectl -n {{ .Release.Namespace }} cp {{ "{POD}" }}:/app/report.html ./report.html -c dashboard
{{- end }}

This completes the Phase 1 MVP pipeline end to end: telemetry collector ->
ingestion & normalization -> waste detector -> savings estimator ->
dashboard. Persistent data
{{- if .Values.persistence.enabled }} lives on a {{ .Values.persistence.size }} PersistentVolumeClaim.
{{- else }} lives on an emptyDir -- enable `persistence.enabled` before running a real pilot so data survives pod restarts.
{{- end }}
